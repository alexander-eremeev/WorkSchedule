# Now in Android Project

Now in Android is a native Android mobile application written in Kotlin. It provides regular news
about Android development. Users can choose to follow topics, be notified when new content is
available, and bookmark items.

## Architecture

This project is a modern Android application that follows the official architecture guidance from Google. It is a reactive, single-activity app that uses the following:

-   **UI:** Built entirely with Jetpack Compose, including Material 3 components and adaptive layouts for different screen sizes.
-   **State Management:** Unidirectional Data Flow (UDF) is implemented using Kotlin Coroutines and `Flow`s. `ViewModel`s act as state holders, exposing UI state as streams of data.
-   **Dependency Injection:** Hilt is used for dependency injection throughout the app, simplifying the management of dependencies and improving testability.
-   **Navigation:** Navigation is handled by Jetpack Navigation 2 for Compose, allowing for a declarative and type-safe way to navigate between screens.
-   **Data:** The data layer is implemented using the repository pattern.
    -   **Local Data:** Room and DataStore are used for local data persistence.
    -   **Remote Data:** Retrofit and OkHttp are used for fetching data from the network.
-   **Background Processing:** WorkManager is used for deferrable background tasks.

## Modules

The main Android app lives in the `app/` folder. Feature modules live in `feature/` and core and shared modules in `core/`.

## Commands to Build & Test

The app and Android libraries have two product flavors: `demo` and `prod`, and two build types: `debug` and `release`.

- Build: `./gradlew assemble{Variant}`. Typically `assembleDemoDebug`.
- Fix linting/formatting: `./gradlew spotlessApply`
- Run local tests: `./gradlew {variant}Test`
- Run single test: `./gradlew {variant}Test --tests "com.example.myapp.MyTestClass"`
- Run local screenshot tests: `./gradlew verifyRoborazziDemoDebug`

### Instrumented tests

- Gradle-managed devices to run on device tests: `./gradlew pixel6api31aospDebugAndroidTest`. Also `pixel4api30aospatdDebugAndroidTest` and `pixelcapi30aospatdDebugAndroidTest`.

### Creating tests

#### Instrumented tests

- Tests for UI features should only use `ComposeTestRule` with a `ComponentActivity`.
- Bigger tests live in the `:app` module and they can start activities like `MainActivity`.

#### Local tests

- [kotlinx.coroutines](https://github.com/Kotlin/kotlinx.coroutines) for most assertions
- [cashapp/turbine](https://github.com/cashapp/turbine) for complex coroutine tests
- [google/truth](https://github.com/google/truth) for assertions

## Continuous integration

- The workflows are defined in `.github/workflows/*.yaml` and they contain various checks.
- Screenshot tests are generated by CI, so they shouldn't be checked into the repo from a workstation.

## Version control and code location

- The project uses git and is hosted in https://github.com/android/workschedule.

# Проект «Now in Android»

«Now in Android» — это нативное мобильное приложение для Android, написанное на языке Kotlin. Оно предоставляет актуальные новости, касающиеся разработки под Android. Пользователи могут подписываться на интересующие их темы, получать уведомления о появлении новых материалов и добавлять контент в закладки.

## Архитектура

Данный проект представляет собой современное Android-приложение, разработанное в соответствии с официальными рекомендациями Google по архитектуре. Это реактивное приложение, построенное по принципу «одна активность» (single-activity), в котором используются следующие подходы и инструменты:

-   **Пользовательский интерфейс (UI):** Полностью создан с помощью Jetpack Compose; включает компоненты Material 3 и адаптивные макеты для экранов различных размеров.
-   **Управление состоянием:** Реализовано на основе однонаправленного потока данных (Unidirectional Data Flow — UDF) с использованием корутин Kotlin (Kotlin Coroutines) и потоков (`Flow`). `ViewModel` выступают в роли держателей состояния, предоставляя его в виде потоков данных.
-   **Внедрение зависимостей (Dependency Injection):** Для управления зависимостями во всем приложении используется библиотека Hilt, что упрощает их организацию и повышает тестируемость кода.
-   **Навигация:** Реализована с помощью Jetpack Navigation 2 для Compose, что обеспечивает декларативный и типобезопасный переход между экранами.
-   **Работа с данными:** Слой данных построен на основе паттерна «репозиторий» (repository pattern).
-   **Локальные данные:** Для их хранения используются библиотеки Room и DataStore.
-   **Удаленные данные:** Для получения данных из сети используются Retrofit и OkHttp.
-   **Фоновые задачи:** Для выполнения отложенных фоновых операций применяется WorkManager.

## Модули

Основное Android-приложение находится в директории `app/`. Функциональные модули (feature modules) расположены в папке `feature/`, а базовые и общие модули — в папке `core/`.

## Команды для сборки и тестирования

Приложение и Android-библиотеки поддерживают два варианта продукта (product flavors) — `demo` и `prod`, а также два типа сборки (build types) — `debug` и `release`.

- Сборка: `./gradlew assemble{Variant}`. Например, `assembleDemoDebug`. - Исправление стиля кода/форматирования: `./gradlew spotlessApply`
- Запуск локальных тестов: `./gradlew {variant}Test`
- Запуск отдельного теста: `./gradlew {variant}Test --tests "com.example.myapp.MyTestClass"`
- Запуск локальных скриншот-тестов: `./gradlew verifyRoborazziDemoDebug`

### Инструментальные тесты (Instrumented tests)

- Для запуска тестов на устройствах используются управляемые Gradle виртуальные устройства (Gradle-managed devices), например: `./gradlew pixel6api31aospDebugAndroidTest`. Также доступны `pixel4api30aospatdDebugAndroidTest` и `pixelcapi30aospatdDebugAndroidTest`.

### Создание тестов

#### Инструментальные тесты

- Тесты для элементов пользовательского интерфейса (UI) должны использовать только `ComposeTestRule` в сочетании с `ComponentActivity`.
- Более масштабные тесты находятся в модуле `:app`; они могут запускать такие Activity, как `MainActivity`.

#### Локальные тесты

- [kotlinx.coroutines](https://github.com/Kotlin/kotlinx.coroutines) — для большинства проверок (assertions).
- [cashapp/turbine](https://github.com/cashapp/turbine) — для сложных тестов, связанных с корутинами (coroutines).
- [google/truth](https://github.com/google/truth) — для выполнения проверок (assertions).

## Непрерывная интеграция (CI)

- Рабочие процессы (workflows) определены в файлах `.github/workflows/*.yaml` и включают в себя различные проверки.
- Скриншот-тесты генерируются в рамках CI, поэтому их не следует добавлять в репозиторий с локальной рабочей станции.
