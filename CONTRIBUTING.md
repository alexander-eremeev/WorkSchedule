# How to become a contributor and submit your own code

## Contributor License Agreements

We'd love to accept your sample apps and patches! Before we can take them, we
have to jump a couple of legal hurdles.

Please fill out either the individual or corporate Contributor License Agreement
(CLA).

  * If you are an individual writing original source code and you're sure you
    own the intellectual property, then you'll need to sign an [individual CLA](https://developers.google.com/open-source/cla/individual).
  * If you work for a company that wants to allow you to contribute your work,
    then you'll need to sign a [corporate CLA](https://developers.google.com/open-source/cla/corporate).

Follow either of the two links above to access the appropriate CLA and
instructions for how to sign and return it. Once we receive it, we'll be able to
accept your pull requests.

## Contributing A Patch

1. Submit an issue describing your proposed change to the repo in question.
1. The repo owner will respond to your issue promptly.
1. If your proposed change is accepted, and you haven't already done so, sign a
   Contributor License Agreement (see details above).
1. Fork the desired repo, develop and test your code changes.
1. Ensure that your code adheres to the existing style in the sample to which
   you are contributing. Refer to the
   [Google Cloud Platform Samples Style Guide](https://github.com/GoogleCloudPlatform/Template/wiki/style.html) for the
   recommended coding standards for this organization.
1. Ensure that your code has an appropriate set of unit tests which all pass.
1. Submit a pull request.

# Как стать участником проекта и предложить свой код

## Соглашения о предоставлении прав (Contributor License Agreements — CLA)

Мы будем рады принять ваши примеры приложений и исправления! Однако, прежде чем мы сможем их включить в проект, необходимо урегулировать некоторые юридические вопросы.

Пожалуйста, заполните соответствующее соглашение о предоставлении прав (Contributor License Agreement, CLA) — для физических лиц или для организаций.

* Если вы — частное лицо, самостоятельно пишете исходный код и обладаете правами интеллектуальной собственности на него, вам необходимо подписать [соглашение для физических лиц (individual CLA)](https://developers.google.com/open-source/cla/individual).
* Если вы работаете в компании, которая разрешает вам вносить вклад в проект, вам потребуется подписать [соглашение для организаций (corporate CLA)](https://developers.google.com/open-source/cla/corporate).

Перейдите по одной из указанных выше ссылок, чтобы ознакомиться с нужным соглашением и инструкциями по его подписанию и отправке. Как только мы получим документ, мы сможем принимать ваши запросы на включение кода (pull requests).

## Внесение исправлений

1. Создайте задачу (issue) в соответствующем репозитории, описав предлагаемые вами изменения.
1. Владелец репозитория оперативно ответит на ваше обращение.
1. Если ваше предложение будет принято, подпишите соглашение о предоставлении прав (CLA), если вы еще этого не сделали (подробности см. выше).
1. Создайте форк (fork) нужного репозитория, внесите изменения в код и протестируйте их.
1. Убедитесь, что ваш код соответствует стилю, принятому в том примере, который вы дополняете. Рекомендуемые стандарты написания кода для данной организации можно найти в [руководстве по стилю для примеров Google Cloud Platform](https://github.com/GoogleCloudPlatform/Template/wiki/style.html).
1. Убедитесь, что для вашего кода подготовлен соответствующий набор модульных тестов (unit tests) и что все они успешно проходят проверку.
1. Отправьте запрос на включение кода (pull request).
